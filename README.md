## Key Learning

1. **DOM과 Event**: 클릭 또는 Form 제출 이벤트가 발생하면 입력값을 읽고, HTML 요소를 생성하거나 변경해서 화면에 반영합니다.
2. **Array를 활용한 CRUD**: `push()`로 추가하고, `forEach()`로 조회하며, `find()`로 수정할 객체를 찾고, `filter()`로 삭제 대상을 제외합니다.
3. **데이터와 화면의 연결**: Array 변경만으로 화면이 자동 갱신되지는 않습니다. `renderTrips()`를 호출해 현재 데이터와 표를 맞춥니다. Validation은 데이터를 변경하기 전에 실행합니다.

## CRUD Service

### 주제와 데이터 Field

서비스 주제는 여행 관리입니다. 초기 여행 데이터는 3개이며, 여행 하나는 다음 6개 Field를 가진 객체입니다. 자동 생성되는 `id` 외에 사용자가 입력하는 Field는 5개입니다.

| Field         | 의미                          | 자료형 / 입력 방식 |
| ------------- | ----------------------------- | ------------------ |
| `id`          | 여행의 고유 번호              | 숫자, 자동 생성    |
| `title`       | 여행 이름                     | 문자열, text       |
| `destination` | 여행지                        | 문자열, text       |
| `startDate`   | 출발일                        | 문자열, date       |
| `budget`      | 예산                          | 숫자, number       |
| `status`      | 예정 / 계획중 / 진행중 / 완료 | 문자열, select     |

### Create

Form 제출 시 `preventDefault()`로 기본 제출 동작을 막고 입력값을 읽습니다. Validation을 통과하고 `editingId`가 `null`이면 여행 객체를 만들어 `trips.push(newTrip)`으로 추가합니다. `nextId`는 4부터 시작하며 추가할 때 증가하므로, 여행을 삭제해도 새 ID가 기존 ID와 중복되지 않습니다.

### Read

`renderTrips()`는 기존 `<tbody>` 내용을 비우고 `trips.forEach()`로 여행마다 `<tr>`을 생성합니다. 각 Field는 `<td>`의 `textContent`에 넣습니다. 페이지 최초 실행과 데이터 추가·수정·삭제 후 함수를 호출합니다.

### Update

[수정] 버튼을 누르면 해당 여행의 ID를 `editingId`에 저장하고 기존 내용을 Form에 채웁니다. 제출 버튼의 글자는 [저장]으로 바뀝니다. 제출 시 Validation을 다시 거친 뒤 `find()`로 해당 객체를 찾아 5개 입력 Field를 변경합니다. 이때 `push()`는 실행하지 않으므로 여행 개수와 ID가 유지됩니다.

### Delete

[삭제] 버튼을 누르면 `confirm()`으로 삭제 여부를 확인합니다. 취소하면 처리를 종료합니다. 확인하면 `filter()`로 삭제 대상과 ID가 다른 여행만 남긴 Array를 만들어 `trips`에 다시 저장합니다. 화면의 HTML 요소만 지우는 방식이 아니라 Array에서도 제거한 뒤 표를 다시 출력합니다. 수정 중인 여행을 삭제하면 Form과 수정 상태도 초기화합니다.

### Validation

| 조건                   | 검증 방법                                     |
| ---------------------- | --------------------------------------------- |
| 여행 이름 2글자 이상   | `trim()` 후 `title.length < 2` 확인           |
| 여행지 필수            | `trim()` 후 빈 문자열인지 확인                |
| 출발일 필수            | 빈 문자열인지 확인                            |
| 예산이 숫자이고 0 이상 | `Number.isNaN(budget)` 또는 `budget < 0` 확인 |

잘못된 입력에는 `alert()`로 안내하고 `focus()`로 입력창을 선택한 뒤 `return`으로 제출 함수 실행을 종료합니다. 검증 코드가 Create와 Update 분기보다 앞에 있어 두 기능 모두 동일한 검증을 거칩니다. 예산은 현재 `parseInt()`로 정수 변환합니다.

### CSS

페이지의 최대 너비와 가운데 배치, Form 배경과 여백, Input과 Select의 테두리 및 포커스 표시, 버튼과 Table 스타일을 적용했습니다. 삭제 버튼에는 `delete-button` 클래스를 연결해 빨간색으로 구분하고 버튼과 데이터 행에 Hover 효과를 넣었습니다. 좁은 화면에서는 표를 감싼 `table-container` 영역을 가로로 스크롤할 수 있습니다.

## JavaScript

| 기능                         | 코드에서의 역할                                                      |
| ---------------------------- | -------------------------------------------------------------------- |
| `querySelector()`            | 선택자에 해당하는 Form, 입력창, 목록 요소를 찾습니다.                |
| `addEventListener()`         | 클릭과 제출 이벤트에 실행할 함수를 등록합니다.                       |
| `preventDefault()`           | Form 제출에 따른 기본 페이지 이동을 막습니다.                        |
| `createElement()`            | 목록 항목, 표의 행과 셀, 버튼을 만듭니다.                            |
| `appendChild()` / `append()` | 생성한 요소를 부모 요소에 붙입니다.                                  |
| `textContent`                | 요소에 글자를 넣습니다. 사용자 입력을 HTML 코드로 해석하지 않습니다. |
| `value`                      | 입력값을 읽거나 수정할 기존 값을 입력창에 넣습니다.                  |
| `split()` / `trim()`         | DOM 실습에서 쉼표로 문자열을 나누고 앞뒤 공백을 제거합니다.          |
| `forEach()`                  | Array의 각 항목에 대해 콜백 함수를 실행합니다.                       |
| `push()`                     | Array 끝에 새 여행 객체를 추가합니다.                                |
| `find()`                     | 조건에 맞는 첫 번째 여행 객체를 반환합니다.                          |
| `filter()`                   | 조건에 맞는 항목만 포함한 새 Array를 반환합니다.                     |
| `remove()`                   | DOM 실습에서 해당 목록 항목을 화면에서 제거합니다.                   |
| `reset()`                    | Form 입력 요소를 HTML의 기본값으로 되돌립니다.                       |
| `confirm()`                  | 삭제 확인 여부를 참 또는 거짓으로 반환합니다.                        |
| `renderTrips()`              | 직접 작성한 함수로, 현재 Array를 기준으로 표를 다시 만듭니다.        |

`() => {}`는 React 전용 문법이 아니라 JavaScript의 화살표 함수입니다. `forEach(function (item) { ... })`의 `item`은 현재 처리할 Array 항목을 전달받는 매개변수입니다.

## Problem & Solution

| 문제                                                      | 원인과 해결                                                                                                              |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `li.split is not a function`                              | `<li>`는 문자열이 아닙니다. `input.value.split(",")`로 나눈 값마다 새 `<li>`를 만들었습니다.                             |
| `li is not defined`                                       | 목록 요소 생성 코드가 빠져 있었습니다. 값을 넣기 전에 `createElement("li")`를 실행했습니다.                              |
| `tirm is not a function`                                  | 메서드 이름의 오타였습니다. `trim()`으로 수정했습니다.                                                                   |
| 수정 버튼이 보이지 않거나 `trip is not defined` 발생      | 버튼을 셀에 붙이지 않았고 클릭 코드가 `forEach()` 밖에 있었습니다. 반복문 안에서 버튼과 이벤트를 만들고 셀에 붙였습니다. |
| 수정 저장 시 새 여행이 추가됨                             | 제출 시 항상 `push()`를 실행했습니다. `editingId`로 추가와 수정을 나눴습니다.                                            |
| 삭제 코드 추가 후 `Maximum call stack size exceeded` 발생 | `renderTrips()` 내부에서 자신을 다시 호출했습니다. 갱신 호출을 삭제 클릭 함수 안으로 옮겼습니다.                         |
| 삭제 버튼이 빨간색으로 표시되지 않음                      | CSS 클래스가 버튼에 연결되지 않았습니다. `classList.add("delete-button")`를 적용했습니다.                                |
| 삭제 후 새 ID가 중복될 가능성                             | Array 길이로 ID를 계산하면 삭제 후 중복될 수 있습니다. 별도로 증가하는 `nextId`를 사용했습니다.                          |

## Reflection

이번 실습에서는 화면의 요소와 Array의 데이터가 서로 다른 대상이라는 점을 배웠습니다. DOM 실습은 목록 요소를 직접 삭제하지만 CRUD 서비스는 Array를 먼저 변경한 뒤 화면을 다시 만듭니다. 수정 기능도 새 객체 추가와 기존 객체 변경을 구분해야 합니다.

현재 데이터는 메모리에만 저장되므로 새로고침하면 초기 여행 3개로 돌아갑니다. 이는 Array를 저장소로 사용하는 이번 과제의 동작이며, 새로고침 이후에도 유지하려면 `localStorage` 등의 별도 저장 방법이 필요합니다. 앞으로는 데이터의 영구 저장과 수정 취소 기능의 구현 방법을 더 알아볼 수 있습니다.
